## Summary

CHF onset in Synthea is drawn from age and sex alone. Prior conditions, vital
signs, or prior medication history have no bearing on whether a patient is
selected. Pre-diagnosis records in the scrubbed cohort are largely
uninformative, with one statistically strong exception: CHF patients on
antihypertensives are more intensively treated than age- and sex-matched
controls on the same drugs. The cause of this difference was checked against
every available mechanism in the Synthea source — age, sex, blood pressure
modifications from the CHF module, and cross-module attribute propagation — and
none explains it. It is left as an open question.

All four leak checks pass at pop10000 scale. No label information survives in
pre-diagnosis records.

### Open question: mechanism unexplained

The HCTZ/lisinopril gap among hypertensives was checked against every testable
mechanism in the Synthea source:

- **Age and sex**: controlled by exact birth year + sex matching; not the cause.
- **Blood pressure changes from the CHF module**: the CHF module sets no blood
  pressure vital sign at any point before `CHF Condition Start`. The only BP
  check in the CHF module is a post-diagnosis ICU routing check
  (`Systolic BP < 90`). Not the cause.
- **`chf` attribute propagation**: the `chf` attribute is set once, at `CHF
  Condition Start`, with zero simulated time before it. The hypertension module's
  `Check for Exclusions` reads `chf is not nil` to suppress *new* hypertension
  onsets in CHF patients — it does not affect ongoing treatment for patients
  who already have hypertension. Not the cause.
- **Reason codes**: no diuretic or ACE prescription names CHF as its reason.
  The gap is not a labeling artifact.

The first-start timing shows CHF positives on HCTZ started the drug mostly
5–10 years before CHF (71.8%), while negatives were more spread across earlier
periods. This is consistent with CHF-positive hypertensive patients having
their hypertension onset and subsequent treatment escalation occurring closer in
time to CHF onset — but what drives that clustering in the Synthea simulation
is not resolved from module source inspection alone.

**This is listed as an open question.** The gap is real in the data, the
mechanism is not explained by the factors checked, and no prescription names
CHF as its reason. It does not represent a label leak.

## Module source: how CHF onset is determined

From `congestive_heart_failure.json`:

**Entry path:** `Initial` → `Age Guard` (requires age ≥ 20) → `Determine CHF`

**`Determine CHF`** is a sex-stratified probability draw with no prior-condition
guards. Age-bucket distributions:

| Sex | Age 20–39 | Age 40–59 | Age 60–79 | Age 80+ |
|-----|-----------|-----------|-----------|---------|
| Male | 0.003 | 0.012 | 0.128 | 0.788 |
| Female | 0.002 | 0.017 | 0.120 | 0.813 |

After the draw, an age-bucket Delay state simulates waiting until the target
age. Then `Determine Type` assigns HFrEF (39%), HFmEF (13%), or HFpEF (48%),
followed by LVEF and NYHA class SetAttribute states. From there:

```
CHF onset → [4 counter resets] → [6 instantaneous Symptom states] → CHF Condition Start
```

No Delay states exist between `CHF onset` and `CHF Condition Start`. The
`chf` attribute (`assign_to_attribute: "chf"`) is set at `CHF Condition Start`
and nowhere else in the module.

No prior conditions, lab values, medications, or vital-sign thresholds gate
CHF onset. The diagnosis is decided by age and sex alone.

## Applying this to other conditions

Three findings from this analysis generalize to any condition studied with this
pipeline:

**1. Presenting-symptom scrub issue.**
Synthea assigns symptom states (dyspnea, fatigue, etc.) between the internal
onset state and the ConditionOnset that scrub.py uses as the cutoff. For CHF,
these six Symptom states are instantaneous (no time delay). For other
conditions, the gap may be non-zero: if Synthea inserts a Delay state between
internal onset and ConditionOnset, those symptoms would appear in pre-cutoff
records as legitimate antecedents rather than leaks. Check each target
condition's module for Delay states between internal onset and the
ConditionOnset that produces the target code.

**2. Module onset guards predict whether history carries signal.**
Each Synthea module has an entry path, and most have prior-condition guards or
attribute checks before onset. Reading those guards tells you directly whether
pre-diagnosis history can predict the label. For CHF, `Determine CHF` has no
guards — history carries no structural signal. For a condition gated on, say,
diabetes or obesity, history would carry signal by construction. Inspecting the
`complex_transition` conditions at `Determine [Condition]` before coding any
antecedent comparison will tell you which differences to expect and which are
artifacts.

**3. Attribute scan is a reusable leak check.**
For any target condition, the pipeline should identify: (a) where the target
attribute is set (`assign_to_attribute` or `SetAttribute`), (b) every module
that reads it, and (c) whether any reading module can affect pre-cutoff records.
The attribute is set once per condition in well-structured Synthea modules. If
a reading module acts before the ConditionOnset — for instance, a module that
increases a comorbidity rate when the attribute is present — that would create a
structural antecedent signal even if no code or text from the target condition
survives. Grep for the attribute name across all modules and trace the
effect-before-diagnosis path. For CHF, every reader fires only after diagnosis.
