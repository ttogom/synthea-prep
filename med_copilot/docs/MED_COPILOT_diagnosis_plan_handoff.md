## Current Working Baseline

The current runner is:

`synthea-prep/scripts/run_med_copilot.py`

It successfully executes the following treatment-plan workflow:

1. free-text patient input
    - Tested with Synthea file `data_run_med_copilot/input/Peter292_Gleichner915_0db4522b-544a-43b1-ad63-3caeb72be2ab.txt`. `run_med_copilot.py` selects the first encounter from that note and cuts the text at the `# Assessment and Plan` section.
2. MED-COPILOT patient normalization
    - Their existing pipeline converts the free text into Subjective / Objective / Assessment format using an LLM using `med_copilot/upstream/templates/SOA_P_TEMPLATE.py`. Note that the Assessment is still included/generated by the LLM. 
3. Retrieval of top 20 similar patient candidates
    - Searches `med_copilot/upstream/soap_with_metadata.json`, an n = 1000 corpus that includes Assessment and Plan, NOT the 36,000 patient database described in the paper. We will need to build out this database using Synthea and/or MIMIC-IV records.
    - Retrieval is hybrid: BioClinicalBERT dense retrieval + keyword retrieval 
4. Cross-encoder reranking to top 5, and the #1 reranked patient’s case + Plan is selected as downstream evidence
5. Key-question generation
    - An LLM (gpt-4o-mini, the released repo uses `self.model` without specifying) is asked to identify what clinical guideline info is needed to make the treatment plan. These become queries to GraphRAG in the subsequent step.
        - The prompt for this uses the `KEY_QUESTION_TEMPLATE` in `med_copilot/upstream/templates/SOA_P_TEMPLATE.py`
6. GraphRAG guideline retrieval
    - runs successfully but there are differences between what the current runner `run_med_copilot.py` does vs. MED-COPILOT (guideline corpus incomplete, the released GraphRAG artifact uses OpenAI text-embedding-3-small, whereas the paper describes BioClinicalBERT). They are described further in sections below. 
7. MED-COPILOT final prompt to the LLM for Plan output is generated
    - target patient S/O/A + #1 similar patient’s case/Plan + GraphRAG guideline evidence → final prompt
        - specifically, `EVALUATE_TEMPLATE_KEYINFO` in `med_copilot/upstream/templates/SOA_P_TEMPLATE.py`
    - Known issue to fix in `run_med_copilot.py`: GraphRAG returns (response_text, context_data), which is currently passed as an entire object into the prompt. I believe it should only select and pass on response_text but not sure yet -- need to dig deeper.

9. LLM treatment-plan generation
    - The final generation call is commented out in the frozen upstream source; the project runner restores the intended call so the pipeline can execute through treatment-plan generation.

The first full smoke test completed successfully on a single Synthea note saved locally and produced a final treatment plan. This establishes that the major released MED-COPILOT components can execute together end-to-end. **This is an engineering smoke-test milestone, not yet a faithful reproduction of the MED-COPILOT study.**
